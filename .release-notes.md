## What changed

Nothing in the control. The manifest's own commentary gave a wrong second
reason for this control being canvas-only — that a model-driven form has no way
to bind an event. A form script can bind a code component's event with
`addEventHandler`, and that is what Form Action Button is built on. The real
reason is unchanged: this control binds no column, and a model-driven form
places a code component on one.

The button, its properties and its events behave exactly as in 0.1.0; the 39
checks against the built bundle and the four demo presets pass as before.

## What you must do

Nothing. Upgrading from 0.1.0 changes no property, no default and no
behaviour.
